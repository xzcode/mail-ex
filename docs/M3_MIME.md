# M3 — MIME, rich text and attachments

- Schema v3 migrates prior data. Adds per-account plain-text signatures, draft HTML, attachment payload and optional Sent-copy preference. Draft list returns no attachment payload; opening a draft loads its complete data.
- Incoming HTML is parsed and sanitized in Rust with a strict tag allowlist and no retained attributes. No links, images, scripts, CSS, SVG, embedded documents or forms. Plain text is selectable; HTML-only messages have derived text fallback. The original MIME remains cached. Rich text is rendered as sanitized markup, not the original HTML.
- Attachments decoded from cached MIME, listed by deterministic part index, with name, MIME type, decoded size and previewability. Text and raster (PNG/JPEG/GIF/WebP detected by magic) can be previewed; SVG, HTML, PDF and other types use explicit native Save As. Names are stripped of path components and unsafe characters. No attachment is auto-opened or executed. File destinations are chosen via a native dialog, not an arbitrary path accepted from the webview.
- Compose supports plain text and basic rich text (bold, italic, underline, strike, headings, lists, quotes). Paste is plain text; arbitrary remote images, links and HTML styles are deliberately not supported. Rust sanitizes outgoing HTML again. Rich messages use multipart/alternative; attachments use multipart/mixed. Forwarding includes the source's decoded attachments and plain-text quote; recipients and attachments are editable before send.
- User may attach multiple files using the local file picker, remove individual files, save and reopen drafts with their payload. No imposed attachment count/size quota. Current implementation reads complete MIME and attachment data into memory and sends base64 through IPC; streaming and very large files remain future optimization. Existing provider-side message-size limits still apply.
- Signature can be set per account and is inserted on new compose/reply/forward; manual insertion available. Draft autosave while compose is open, every five seconds when dirty and idle, can be disabled; explicit Save remains available. No background send.
- Optional server Sent copy uses IMAP APPEND after SMTP acceptance, only to server-advertised Sent folder. Default off because providers may save automatically. Sent-copy failure is separate from SMTP success and never triggers SMTP retransmission. The next folder sync fetches any saved copy.
- Remaining: native desktop runtime/packaging acceptance; attachment streaming, inline CID rendering, PDF preview, rich paste, signatures with rich HTML, independent native read/compose windows. OAuth not implemented.
