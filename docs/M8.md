# M8 — POP3, calendar and invitations

## POP3
Choose the incoming protocol when adding a password/app-password account. POP3 uses implicit TLS, hostname/certificate verification, mandatory stable UIDL and RETR with dot unescaping. The client never sends DELE. UIDL deduplication is account-scoped; messages disappearing from the server remain cached. Read/star flags are local, not synchronized to the server. Optional Sent copy is local. Server-side moves are IMAP-only. POP3 caches are excluded from generic synchronized-mail cache cleanup because they can be the only surviving copy. Existing configuration fields imap_host/imap_port are retained on disk for compatibility and represent the incoming POP3 endpoint for POP3 accounts. Use port 995 or the provider's explicit TLS port.

## Calendar
Schema v8 includes local events, imported/remote event data, CalDAV source credentials (encrypted with the per-install vault key), and reminder state. Local events can be created, edited and deleted, with a monthly view and daily agenda. Local times are floating in the device timezone, or UTC when supplied; all-day end dates are exclusive. ICS import handles unfolded content lines, date/time values, simple durations, UID, sequence, attendees and organizer; raw event properties and VTIMEZONE are retained for export. Imported and remote events are read-only. Named timezone display retains original wall time; recurring series and exceptions are not expanded, and recurrence editing, conflict resolution and full RFC 5545 compatibility are future work.

CalDAV uses a user-specified HTTPS collection URL, username and app password. The calendar-query REPORT requests calendar-data for VEVENTs. It validates the DAV multistatus, parses all returned items and updates only the local read-only cache in a transaction. Invalid/incomplete responses retain the previous calendar. No remote PUT/DELETE, OAuth CalDAV, discovery or incremental sync yet.

## Invitations
Recognizes METHOD:REQUEST in text/calendar or ICS attachments. The user can explicitly add the event to the local calendar or create an ACCEPTED/DECLINED/TENTATIVE reply draft. Reply is restricted to a configured mailbox that is an invited attendee and targets the organizer; no automatic response. Local saved events can create METHOD:REQUEST drafts. All drafts use the existing compose/outbox flow with a text/calendar attachment; provider-native iMIP inline handling and interoperability are not yet verified. Imported invitations are deduplicated by UID and recurrence ID; updates/cancellations are not reconciled automatically.

## Reminders and notifications
Opt-in native notification setting. New synchronized mail and due local calendar events emit generic counts, not titles or message text. Calendar reminders are claimed once per event sequence while the application runs. Local ambiguous DST times are not auto-resolved. OS permission/display, native scheduler and actual provider compatibility require desktop runtime validation.
