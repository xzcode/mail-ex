# M9 — Native desktop and window workflow

- Desktop build environment: Debian Bookworm, GTK 3, WebKitGTK 4.1, OpenSSL, appindicator dependencies and Xvfb. The project-specific Dockerfile does not install anything into the host operating system. Mount a compatible Rust toolchain, Cargo cache, checkout, and target directory into the build image; do not mount real mail data or secrets.
- Native composer: new compose opens in a separate webview by default after saving a draft; optional inline mode remains. Draft editing reuses a window keyed by draft UUID. Main draft deletion is blocked while that draft's native editor is open. Detached compose reuses existing attachments, rich text, templates, contacts, autosave, signature and durable queue. Closing a modified draft requires confirmation. Queued send closes the composer after durable acceptance; the original scheduler handles delivery.
- Native reader: double-click a mail row or use Open window. Each reader receives a one-time immutable snapshot (including sanitized HTML, labels, invitation and attachment metadata), so it remains safe even when the source cache changes. Remote mutations, reply and attachment save remain in the main reader; the detached reader is deliberately read-only.
- Settings: follow-system/English/Chinese language, light/soft light/gray/dark/system themes, comfortable/compact density, reading font size, reset split widths, configurable polling minutes, independent compose preference, autosave and shortcuts. Settings persist locally.
- Native smoke script starts a debug custom-protocol binary with a temporary HOME and Xvfb/D-Bus session. The debug-only --smoke-fixtures mode creates a separate temporary database, seeds a local draft and imported EML, and opens the independent windows. The script checks main, compose and reader real IPC readiness markers. Run with no network and no personal data for smoke testing.
- Release status: record actual native build, smoke test and package evidence before publishing. Windows/macOS need separate target-platform runners. Do not label source implementation as native validation.

## Native build evidence and reproduction

Use Dockerfile in scripts/native-build. On Linux provide a compatible x86-64 Rust sysroot at /rust, a project Cargo cache at /cargo, checkout at /work, and a separate target at /target. Build in the image:

```sh
npm ci
npm run build
cargo build --manifest-path src-tauri/Cargo.toml --locked --features custom-protocol -j 1
```

For the smoke, mount only the debug binary and scripts/native-smoke.sh, run as a non-root user with no network and temporary HOME. Software rendering was used in the headless container; the WebKit sandbox was not explicitly disabled.

After startup verification:

```sh
npm run tauri -- bundle --debug --bundles deb --features custom-protocol --ci --no-sign
```

Inspect package metadata, extract with dpkg-deb and verify ldd. The initial M9 candidate was a debug DEB; the public preview now uses a separately built optimized DEB. Manual three-platform package workflow is .github/workflows/desktop-packages.yml. Linux optimized build and extracted-DEB IPC smoke passed; Windows native NSIS build succeeded. macOS final DMG verification, installation on a fresh OS and full GUI interaction remain pending. See BUILD_EVIDENCE.md for exact commits, artifact checksum and log details.

## Delivery hardening

Native tray menu (open, sync, quit), opt-in close-to-tray and guarded quit are implemented. The native outbox dispatcher and scheduler share a delivery gate; explicit quit rejects active dispatch and open compose windows. Forced OS shutdown can still interrupt delivery; interrupted messages remain uncertain. Linux close-to-tray checks the status notifier host before hiding. Release profile optimizes the application at level 2 and dependencies at level 1, strips symbols, no LTO. Windows snapshot flushing uses a writable handle. Public HTTPS npm lockfile URLs enable hosted runners. macOS DMG verification mounts the finished installer read-only and checks the embedded app signature; ad-hoc signing is not notarization. See BUILD_EVIDENCE.md for actual results and remaining checks.
