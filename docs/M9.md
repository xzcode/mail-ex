# M9 — Native desktop and window workflow

- Desktop build environment: Debian Bookworm, GTK 3, WebKitGTK 4.1, OpenSSL, appindicator dependencies and Xvfb. The project-specific Dockerfile does not install anything into the host operating system. Mount a compatible Rust toolchain, Cargo cache, checkout, and target directory into the build image; do not mount real mail data or secrets.
- Native composer: new compose opens in a separate webview by default after saving a draft; optional inline mode remains. Draft editing reuses a window keyed by draft UUID. Main draft deletion is blocked while that draft's native editor is open. Detached compose reuses existing attachments, rich text, templates, contacts, autosave, signature and durable queue. Closing a modified draft requires confirmation. Queued send closes the composer after durable acceptance; the original scheduler handles delivery.
- Native reader: double-click a mail row or use Open window. Each reader receives a one-time immutable snapshot (including sanitized HTML, labels, invitation and attachment metadata), so it remains safe even when the source cache changes. Remote mutations, reply and attachment save remain in the main reader; the detached reader is deliberately read-only.
- Settings: follow-system/English/Chinese language, light/soft light/gray/dark/system themes, comfortable/compact density, reading font size, reset split widths, configurable polling minutes, independent compose preference, autosave and shortcuts. Settings persist locally.
- Native smoke script starts a debug custom-protocol binary with a temporary HOME and Xvfb/D-Bus session, waits for the real webview to complete its local IPC initialization, and checks the readiness marker. Run with no network and no personal data for smoke testing.
- Release status: record actual native build, smoke test and package evidence before publishing. Windows/macOS need separate target-platform runners. Do not label source implementation as native validation.
