# M2 / M3 implementation notes

## Folder synchronization
SQLite schema v2 migrates existing account/message data and introduces folders, starred flags, and local drafts. The initial application setup runs migration; concurrent migration rechecks the version under a SQLite write transaction. Folder names remain their original wire representation for server commands, while modified UTF-7 names are decoded for display. The server LIST result determines selectable and special-use folders; unavailable folders retain cached messages. No destructive special-use inference from folder text.

Unified inbox and unread are inbox-only. All cached mail and starred views cover synchronized folders. Initial/manual sync downloads missing messages in bounded batches, then reconciles UIDVALIDITY, UID, seen and flagged state transactionally per folder. Sync all explicitly scans all selectable folders in one account (including provider virtual folders; duplicate physical mail may appear under multiple folders). Automatic polling is opt-in, inbox-only while app runs, with selected interval persisted. No IDLE, native background service or OS notification in this baseline. Failed folder scans do not erase that folder's cache.

## Mutation
Read and star actions validate UIDVALIDITY, perform UID STORE, confirm server result before local update. Move checks source identity and destination belongs to account; requires IMAP MOVE capability and uses UID MOVE, not COPY/DELETE/EXPUNGE fallback. Trash/archive shortcuts only appear for server-declared roles, otherwise manually select destination. No permanent delete. A move's successful server acceptance and destination cache refresh are separate outcomes.

## Compose
Local drafts are SQLite records independent of server draft folders; multiple drafts can be saved/reopened/deleted. Reply uses Reply-To/From; reply-all deduplicates To/Cc and excludes current sending identity from Cc. Forward quotes the plain text body. Reply headers preserve valid Message-ID and References, stored with draft. Attachment forwarding, HTML and rich text are not yet supported. SMTP accepted is not recipient delivery; uncertain delivery is not automatically retried. Saving a draft requires a configured account but no recipients. Successful send removes the local draft separately.

## Settings
Theme, language, pane widths, polling interval persist locally. Account credential, display name, color and outgoing settings may be updated without deleting cache. Changing incoming identity requires adding a separate account to avoid linking old UID cache to a different mailbox.

## Validation
Implementation baseline only until core build, tests, Tauri desktop build and protocol integration have been recorded. No actual accounts or messages are used for automated validation.
