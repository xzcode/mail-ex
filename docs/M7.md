# M7 — Data portability, backup and storage

## Local mail archive
- Multi-file EML import retains original bytes. MBOX uses mboxrd-style From separators and escaping. MBOX processing buffers one message at a time; original EML export is byte exact, while MBOX may normalize the final newline.
- A dedicated local-only archive is indexed by the existing search engine, excluded from automatic sync and sending-account selection. Exact duplicate MIME imports are skipped by SHA-256. Reading and local read/star status are supported; deleting imported mail requires explicit confirmation. Reply/forward selects an actual sending mailbox.
- Export single EML or MBOX by account/folder scope (not just currently displayed page or filters). Export all cached mail is also available.

## Contacts and account configuration
CSV columns: email (required), name, group, notes. Existing case-insensitive email addresses are skipped. Invalid rows are counted. Account JSON is versioned and excludes passwords, tokens and credential key. Imported accounts require new credentials; existing matching configurations are skipped. OAuth endpoints are checked against fixed provider presets.

## Storage and cache
Show SQLite/WAL/SHM bytes, raw MIME byte count, cached/local message counts, drafts/outbox counts. Preview and clear only synchronized mail by account and optional date; never delete local imports, drafts, contacts or outbox. Cleared server cache may be downloaded again. Database compaction is explicit.

## Backup and restore
SQLite VACUUM INTO produces a consistent database copy in a newly created child directory; credential key is included. The manifest records schema version and SHA-256 checksums. Both snapshot and restoration disable queued/sending outbox rows by marking them uncertain. The live database and its delivery queue are unaffected. Restore checks manifest, file hashes, exact schema, quick_check, foreign keys and credential-key matching before selecting a separate new directory. Storage migration likewise copies to a separate directory; activation is on restart. Existing data is never overwritten. Changes to the live database after the copy are not included; quit before continuing work in the new copy.

Backups are **not encrypted** and contain private mail and a usable credential key. Unix private file/directory permissions are applied; Windows relies on the selected directory's ACLs. Keep backups in trusted private storage. Checksums detect accidental corruption, not adversarial tampering; restore only trusted backups. Current restore accepts this schema version only. Do not hand-edit the manifest or live SQLite files. Native dialog/path-switch runtime remains to be tested.

## Remaining
Passphrase-encrypted portable backups, backward-version restore compatibility, native desktop runtime and file-dialog acceptance, streaming large MIME/attachments, comprehensive security audit, and cross-platform packaging.
