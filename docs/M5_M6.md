# M5 / M6 — Local organizer and durable outbox

## Local organization (schema v6)

- Contacts have email, display name, group and notes; email is unique case-insensitively. The compose fields suggest contacts by name, address or group and support choosing a recipient with keyboard or mouse. No contacts are uploaded anywhere.
- Templates have subject, plain body and optional sanitized rich HTML. They can be created/edited in the organizer or saved from the composer. Applying a template replaces subject and body after confirmation, retaining recipients and attachments.
- Saved searches persist account/view/folder scope, keywords, sender/recipient/subject/category/date filters. Reopening runs the saved definition against the current cache.
- Rules match sender, recipient, subject and body substrings (AND or OR), optionally scoped to one account. At least one condition is required. Enabled rules add a local category when an inbox message is newly inserted, within the same SQLite transaction. Preview and explicit application to existing cached inbox mail are supported. Explicit application is additive/idempotent; disabling a rule stops future automatic labeling but does not remove prior labels. Deleting a rule removes its associations. Local categories follow cached inbox entries and may disappear if the cached entry is removed/moved; they are not synchronized server labels. No automatic move, deletion, reply, or outbound network action is triggered by classification.
- Category filters combine with the existing FTS5 index. No artificial contact, template, rule or saved-search count quota is imposed.

## Durable local outbox

- Compose immediate send or explicit scheduled send queues a validated MIME payload with a stable UUID request ID and due time. Queue insert and removal of a corresponding local draft are atomic. A replay of the same request cannot create another delivery record.
- Each sender claims only an eligible queued row using an immediate database transaction, commits the 'sending' state before SMTP and never automatically requeues a claimed message. Concurrent processes cannot claim the same queued item twice. SMTP acceptance is recorded separately from optional Sent APPEND status. A failure or uncertain outcome is marked 'uncertain'; no retry is performed. A crash after claim may leave 'sending'; the user may explicitly mark interrupted/uncertain after ensuring another instance is not active. Copying an uncertain message to a new draft requires user confirmation and server verification.
- Queued mail can be canceled before claim. Completed/canceled/uncertain records can be copied into a new draft or deleted locally. An account with queued or sending messages cannot be removed until those are resolved.
- A desktop background worker polls every five seconds while the application process runs, including when the UI is minimized. Due mail missed while closed is eligible on the next launch. No always-on service or guarantee of exact-time delivery. System clock/network availability and SMTP provider limits apply.
- State and content are stored locally; message and attachment data are not encrypted. Queue and draft payloads are buffered in memory. No real external mailbox is used for tests.
